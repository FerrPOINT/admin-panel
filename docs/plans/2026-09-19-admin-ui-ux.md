# UI/UX Admin Panel: операционный обзор и компактные рабочие экраны

## Цель и сценарии

Администратор за первый экран понимает состояние сервисов, наличие ожидающих
действий и последние изменения. Оператор быстро находит сервис, пользователя,
токен или событие аудита. Наблюдатель получает те же сведения без изменяющих
действий. На узком экране названия и статусы важнее технических идентификаторов.

## Роли и данные

- Обзор: `GET /api/v1/services`, `GET /api/v1/branding/revisions`,
  `GET /api/v1/audit-events`. Разрешён текущим вошедшим пользователям.
- Каталог и карточка сервиса: текущие registry/declaration endpoints. Изменения
  доступны только роли с `canMutate`.
- Пользователи и токены: существующие прокси Central Auth. Токен показывается
  только при создании, как и сейчас.
- Журнал: `GET /api/v1/audit-events` с существующими фильтрами и постраничной
  загрузкой. Исходные metadata и request ID доступны в раскрываемых деталях.
- Брендинг и конфигурации: существующий versioned API, без изменения контракта.

## Компоненты и порядок

1. Инициализировать локаль `ru` для shared UI; убрать предупреждение i18n.
2. Перестроить обзор в компактный операционный экран: статусы сервисов,
   ожидающие декларации, последние события и ссылки на рабочие разделы.
3. Заменить карточную ленту аудита строками с раскрываемыми деталями, читаемой
   датой и короткими идентификаторами. Сохранить фильтры и пагинацию.
4. Дать явные accessible names цветовым полям брендинга и переключателям
   capabilities; сделать цели частых действий удобнее для касания.
5. Привести вторичные подписи и состояния реестра, карточки сервиса,
   конфигураций и настроек к одному русскоязычному стилю.

## Состояния

- Loading: видимый текст состояния, без фиктивных нулей в статистике.
- Empty: отдельное сообщение со ссылкой на следующий доступный шаг.
- Error: сообщение рядом с неудавшимся блоком и действие повторной загрузки.
- Partial failure: работающие блоки остаются видимыми; ошибка аудита не скрывает
  состояние сервисов.
- Disabled/pending: статус отображается текстом вместе с цветом.
- Mobile 375 px: строки перестраиваются, детали остаются раскрываемыми, нет
  горизонтального переполнения.

## Проверка

- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` в `frontend`.
- Браузер: обзор, аудит, брендинг и карточка сервиса при 1280x900 и 375x812;
  нет i18n warning и content overflow.
- Проверить раскрытие деталей, работу фильтров, keyboard focus и именование
  интерактивных элементов.
