# Состояния повторной загрузки журнала аудита

## Сценарий

После успешного просмотра журнала повторный запрос может завершиться ошибкой. React Query сохраняет предыдущее `data`, но показывать его вместе с ошибкой и прежним итогом нельзя: оператор примет устаревшие события за текущий ответ.

## Решение

- Пока страница загружается или обновляется, показывать состояние загрузки без старых строк и счётчика.
- При ошибке скрывать старые строки и итог, оставлять фильтры и номер страницы, предлагать retry.
- Корректировать номер страницы после уменьшения `total` только по успешному завершённому ответу.
- Backend API и формат audit event не менять.

## Проверки

- После успешного ответа имитировать повторную загрузку и ошибку: старые события и итог отсутствуют, retry возвращает актуальную страницу.
- Сохранить существующие тесты фильтров, точной пагинации и пустого результата; прогнать frontend lint, typecheck, unit и production build в CI.
- На живом стенде проверить реальный audit GET после административной мутации и отказ сети, а также mobile/keyboard в трёх темах до merge.
