# Каталог сервисов: поиск, страницы и безопасные состояния форм

## Сценарии и данные

- Администратор и наблюдатель ищут сервис по названию, ключу или команде, фильтруют по состоянию и просматривают каталог по 20 записей. Источник данных остаётся `GET /api/v1/services`; фильтрация и пагинация выполняются в UI без изменения API.
- При ошибке загрузки список не показывает устаревшие строки React Query; повторный запрос доступен без потери фильтров. Пустой каталог и пустой результат поиска различаются.
- Пользователь с `canMutate` создаёт сервис или отправляет новую декларацию. Пока запрос выполняется, поля, переключатели и закрытие формы недоступны. При ошибке черновик остаётся, ошибка видна рядом с действием; успешное сообщение появляется только после ответа API.
- Наблюдатель может читать каталог и карточку, но не видит изменяющих действий.

## Проверки

- Unit: 25 записей дают страницы 20/5, изменение поиска или статуса возвращает на первую страницу; ошибка после успешной загрузки скрывает прежние строки и допускает retry.
- Unit: create/patch pending блокирует ввод и закрытие, ошибка сохраняет черновик, успех сбрасывает форму; observer не получает команд изменения.
- CI: lint, typecheck, unit и production build; после восстановления свободного места — live browser QA на 320/375/768/1280 px, во всех темах, keyboard и axe.
