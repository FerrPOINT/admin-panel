# Журнал аудита: фильтры и точная пагинация

## Сценарий и роли

Администратор и оператор находят административное событие по понятному названию
действия и типу сущности, затем переходят между страницами без пустой последней
страницы. Наблюдатель использует тот же read-only сценарий, если доступ разрешён
серверной ролью. Журнал не меняет данные и сохраняет раскрываемые технические
детали события.

## Контракт и источник данных

`GET /api/v1/audit-events` сохраняет поля `events` и `total`. `total` означает
полное число записей после применения `action` и `entity_type`, до `limit` и
`offset`; массив `events` содержит только запрошенную страницу. Это исправляет
текущую ошибочную семантику `total = events.len()` без переименования поля.
Оба SQL-запроса применяют одинаковые точные фильтры. Пустая страница за пределом
выдачи возвращает `events: []` и действительное `total`.

## Интерфейс

Панель фильтров: выбор действия по русскому названию, тип сущности, включая
«Пользователь». Для неизвестного действия есть режим «Точный код»: поле и
кнопка «Применить»; выбор режима и набор текста не отправляют запрос. Переключение готового
варианта или типа сущности сбрасывает номер страницы. Строки журнала остаются
компактными, детали раскрываются по требованию.

Нижняя строка показывает диапазон и общий объём, например «21–40 из 40».
Кнопка «Вперёд» недоступна на последней полной странице. Если число событий
уменьшилось, открытая страница возвращается к последней существующей. Загрузка, ошибка и
пустой результат различимы; после ошибки доступен повтор запроса. На ширине
375 px фильтры переносятся без горизонтального переполнения, действия имеют
доступные имена и цель от 40 px.

Диалог создания API-токена проверяется отдельно: подписи чекбоксов доступов
должны давать кликабельную область не менее 40 px по высоте. Изменений в
контракте токенов не требуется.

## Проверка

- Backend: одинаковые фильтры для COUNT и списка, `total` при 0, 20 и 40
  событиях, пустая страница после конца выдачи, отрицательный offset.
- Frontend: выбор «Пользователь», точный код только после применения, сброс
  страницы при смене фильтра, диапазон и disabled «Вперёд» на 20/40.
- Isolated browser: 375/1280/1920/2560 px, диалог токена, keyboard/Escape,
  loading/empty/error, отсутствие лишних GET и любых изменяющих запросов.
- `cargo fmt`, `cargo clippy`, `cargo test`, OpenAPI drift; `pnpm lint`,
  `pnpm typecheck`, `pnpm test`, `pnpm build`.

Live Admin Panel и его volumes не используются для тестовых записей.
