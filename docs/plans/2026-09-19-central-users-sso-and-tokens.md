# Центральные пользователи, SSO и API-токены

## Цель

Подключить Admin Panel к браузерному SSO Central Auth и дать вошедшему
пользователю единый интерфейс управления центральными учётными записями и
личными API-токенами. Admin Panel не хранит пароли, сессии, setup-токены или
копию каталога пользователей.

## Объём

- заменить локальную форму входа на OIDC Authorization Code + PKCE;
- принимать callback только после проверки `state`, `nonce`, issuer,
  audience, подписи и срока действия;
- проксировать список, создание, изменение имени, повторную отправку ссылки и
  отключение/восстановление пользователей в Central Auth;
- проксировать выпуск и отзыв личных токенов, показывая секрет только в ответе
  создания;
- загружать допустимые сервисы и scopes из версионируемого контракта Central
  Auth, не дублируя продуктовый каталог во frontend Admin Panel;
- сохранять в локальном audit успешные административные изменения с
  центральным `sub` вызывающего пользователя;
- скрыть UI назначения исторических локальных ролей; таблицы и API совместимости
  пока не удалять;
- при недоступности Central Auth возвращать явную временную ошибку без
  локального парольного fallback.

## Проверки

- backend fmt, clippy, unit/integration и release build;
- frontend lint, typecheck, unit и production build;
- контрактная проверка недоступного каталога scopes и сохранения черновика при
  ошибке выпуска токена;
- живые сценарии: создание пользователя, установка пароля из Mailpit, вход,
  отключение/восстановление, выпуск/ограничение/отзыв токена и audit;
- Playwright на мобильном и desktop, keyboard-only и axe;
- отсутствие токенов в URL, логах и browser storage.
