# Идентификатор созданного пользователя в аудите

## Проблема

Живое создание через Admin Panel возвращает новую центральную учётку, но
`central_user.created` сохраняет `entity_id=null`. Событие нельзя связать с
созданным пользователем. Другие операции уже записывают UUID из пути запроса.

## Решение

- После успешного ответа Central Auth прочитать UUID из существующего `id`.
- Записать его в audit Admin Panel, сохранив инициатора и действие.
- Вернуть неизменные status, JSON и заголовки успешного ответа.
- Невалидный либо отсутствующий UUID считать ошибкой внешнего контракта (502),
  не записывать ложный успешный audit. Ответ об ошибке upstream не менять.
- Не изменять владение пользователями, авторизацию, схемы БД и API задач.

## Проверки

Изолированная PostgreSQL-проверка handler с синтетическим HTTP upstream:
201 и правильный UUID, 201 с невалидным/отсутствующим UUID, 409 без success audit;
проверка сохранения ответа, инициатора и отсутствия персональных данных в metadata.
Полные backend fmt/clippy/tests/build и OpenAPI drift — локально. После безопасного
обновления рабочего образа повторить no-mock создание через UI и проверить UUID
в audit; прежний живой результат с `entity_id=null` не считать закрытием.
