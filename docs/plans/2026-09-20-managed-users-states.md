# Управление пользователями: страницы и состояния действий

## Сценарии

- Каталог Central Auth остаётся источником истины. Admin Panel получает до 100 записей по `q` и `offset`, показывает 20 на странице; на точной границе 100 заранее проверяет наличие следующей партии, чтобы кнопка «Далее» не вела на ложную пустую страницу. Ошибка проверки следующей партии имеет отдельный retry.
- При ошибке списка прежние строки не выглядят актуальными; поиск, текущая страница и повторный запрос остаются доступны. Пустой каталог и пустая страница после изменения данных различаются.
- Во время создания/изменения пользователя поля, закрытие диалога и повторная отправка недоступны. Ошибка сохраняет черновик и видна в диалоге. Успех закрывает форму только после ответа сервера.
- Если учётка создана, но письмо не доставлено, форма показывает отдельный режим повторной отправки с неизменяемыми данными. Успешная повторная отправка не называется новым созданием и обновляет список. Статусный диалог нельзя отменить во время запроса.
- API, авторизация, парольная модель и статусные значения Central Auth не меняются.

## Проверки

- Unit: 100 записей без продолжения и 101 запись, ошибка lookahead/retry, отсутствие устаревших строк после ошибки и retry.
- Unit: pending lock для создания и статуса, сохранение формы при ошибке, частичный успех доставки и повтор без второго создания, обновление списка после повторной отправки.
- Frontend lint, semantic lint, typecheck, unit, production build в CI; live no-mock Admin QA после восстановления места на диске.
