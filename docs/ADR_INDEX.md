# Индекс архитектурных решений

## Статус

Реестр содержит принятые решения реализуемого Admin Panel; новые изменения
границ, контрактов и инструментов дополняют соответствующие ADR и планы.

## Правила ведения ADR

- Создавайте ADR для решений, которые трудно или дорого отменить: границы данных, протоколы, auth, модель ролей, хранилище, версии контрактов, развёртывание и наблюдаемость.
- Храните ADR в `docs/adr/` с именем `NNNN-краткое-название.md`, например `0001-модель-авторизации.md`.
- Каждый ADR должен содержать контекст, решение, альтернативы, последствия, статус и дату.
- При замене решения не переписывайте старый ADR: измените его статус на «Заменён» и добавьте ссылку на новый.
- До реализации решения добавьте запись в таблицу ниже и ссылку на соответствующий план в `docs/plans/`.
