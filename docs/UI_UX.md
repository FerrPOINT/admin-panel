# UI/UX: Admin Panel

## Назначение и границы

Admin Panel - отдельное приложение настроек платформы. Оно управляет:

- визуальным брендингом платформы;
- каталогом подключаемых сервисов и их явными возможностями;
- публикуемыми, версионируемыми конфигурациями;
- аудитом изменений;
- состоянием здоровья и соединений.

Панель **не является универсальным удаленным CRUD-клиентом** для данных других сервисов. Она не редактирует пользователей, вакансии, заявки, документы или доменные сущности внешних систем. Внешний сервис представлен только записью каталога, разрешенными возможностями, конечными точками интеграции и диагностическим состоянием.

Центральный сервис авторизации на порту `7701` отвечает только за идентификацию и роли. Интерфейс Admin Panel не хранит и не показывает секреты; секреты не входят в runtime-конфигурации.

## Принципы интерфейса

- Каждый экран объясняет последствия изменения до публикации.
- Черновик, опубликованная версия и история всегда визуально различимы.
- Опасные действия требуют подтверждения с названием объекта или номером версии.
- Статус отображается текстом, иконкой и цветом; цвет не является единственным сигналом.
- Любая операция с конфигурацией оставляет запись аудита: кто, когда, что и почему изменил.
- При недоступности API экран сохраняет последний известный статус с меткой времени, а не имитирует актуальность.

## Навигация и роли

Левая навигация: `Обзор`, `Брендинг`, `Каталог сервисов`, `Конфигурации`, `Аудит`, `Здоровье и соединения`.

Роли приходят из central auth: читатель видит состояние и историю; редактор создает черновики; издатель публикует и откатывает после подтверждения; администратор управляет каталогом интеграций. Неразрешенные действия остаются видимыми, но отключены с пояснением требуемой роли.

## Карта страниц

1. Обзор платформы.
2. Брендинг платформы.
3. Каталог сервисов.
4. Карточка сервиса и возможности интеграции.
5. Черновик конфигурации.
6. Версии и публикация конфигурации.
7. Аудит изменений.
8. Здоровье платформы.
9. Детали соединения.
10. Недостаточные права и системная ошибка как общие состояния.

## Wireframes

### 1. Обзор платформы

```text
+--------------------------------------------------------------------------------+
| Admin Panel                                      [Org] [Профиль]               |
+----------------------+---------------------------------------------------------+
| > Обзор             | Платформа / Обзор                 [Обновить]            |
|   Брендинг           |---------------------------------------------------------|
|   Каталог сервисов   | [Брендинг: опубликован v12] [Сервисы: 8] [Проблемы: 1] |
|   Конфигурации       |                                                         |
|   Аудит              | Последние изменения                Состояние сервисов   |
|   Здоровье           | +------------------------------+  +------------------+ |
|                      | | 10:32  Брендинг v12          |  | Auth       OK    | |
|                      | | 10:08  CRM endpoint changed  |  | CRM     Warning | |
|                      | | 09:45  Config v31 published  |  | Search     OK    | |
|                      | +------------------------------+  +------------------+ |
+----------------------+---------------------------------------------------------+
```

Назначение: быстро показать опубликованное состояние, последние изменения и требующие внимания сервисы. Карточки ведут только к настройкам и диагностике Admin Panel.

### 2. Брендинг платформы

```text
+--------------------------------------------------------------------------------+
| Брендинг платформы             Черновик v13                 [Сохранить] [ ... ]|
+----------------------+---------------------------------------------------------+
|   Обзор             | [Черновик]  Последняя публикация: v12, 12:10             |
| > Брендинг           |---------------------------------------------------------|
|   Каталог сервисов   | Название платформы [________________________]           |
|   Конфигурации       | Логотип            [Загрузить SVG/PNG] [миниатюра]      |
|   Аудит              | Цвета              [Основной #____] [Акцент #____]      |
|   Здоровье           | Поддержка          [email] [URL справки]                |
|                      |                                                         |
|                      | Предпросмотр                                             |
|                      | +---------------------------------------------------+   |
|                      | | [logo]  Название платформы      Войти            |   |
|                      | +---------------------------------------------------+   |
|                      | [Сбросить] [Сохранить черновик] [Запросить публикацию] |
+----------------------+---------------------------------------------------------+
```

Назначение: редактировать только платформенные визуальные параметры. Перед публикацией показывается сравнение с текущей версией и список продуктов, получающих конфигурацию.

### 3. Каталог сервисов

```text
+--------------------------------------------------------------------------------+
| Каталог сервисов                                             [Добавить сервис] |
+----------------------+---------------------------------------------------------+
|   Обзор             | Поиск [________________]  Статус [Все v]  Тип [Все v]   |
|   Брендинг           |---------------------------------------------------------|
| > Каталог сервисов   | Сервис        Тип        Возможности     Состояние       |
|   Конфигурации       |---------------------------------------------------------|
|   Аудит              | CRM Core      API        3 разрешены     [OK]           |
|   Здоровье           | Mail Relay    webhook    1 разрешена     [Warning]      |
|                      | Search        API        2 разрешены     [OK]           |
|                      |                                                         |
|                      | Выбрано 0                                       < 1 2 > |
+----------------------+---------------------------------------------------------+
```

Назначение: вести реестр интеграций, а не данные подключенных систем. Добавление сервиса определяет его владельца, назначение и допустимые возможности; сетевые вызовы к произвольным URL не предлагаются.

### 4. Карточка сервиса и возможности интеграции

```text
+--------------------------------------------------------------------------------+
| Каталог сервисов / CRM Core                    [Отключить] [Сохранить черновик]|
+----------------------+---------------------------------------------------------+
|                      | [Основное] [Возможности] [Конечные точки] [Изменения]  |
|                      |---------------------------------------------------------|
|                      | Владелец [Команда CRM v]  Назначение [Каталог клиентов] |
|                      | Статус   [Включен v]      Документация [https://....]   |
|                      |                                                         |
|                      | Разрешенные возможности                                |
|                      | [x] health.read       Проверка состояния               |
|                      | [x] catalog.lookup    Справочный поиск                 |
|                      | [ ] events.receive    Прием событий                    |
|                      |                                                         |
|                      | Конечные точки (явный allowlist)                       |
|                      | GET  /health          health.read        [Изменить]    |
|                      | POST /v1/lookup       catalog.lookup     [Изменить]    |
|                      | [+ Добавить конечную точку]                            |
+----------------------+---------------------------------------------------------+
```

Назначение: задавать разрешенный контракт интеграции. Для каждой конечной точки указываются метод, путь, capability, тайм-аут и ожидаемая проверка здоровья. Секреты, токены и произвольные операции с удаленными данными отсутствуют.

### 5. Черновик конфигурации

```text
+--------------------------------------------------------------------------------+
| Конфигурации / Черновик v31                         [Проверить] [Сохранить]    |
+----------------------+---------------------------------------------------------+
|                      | Область: [Общая платформа v]  Получатели: 4 продукта    |
|                      |---------------------------------------------------------|
|                      | Изменения                                               |
|                      | - brand.primaryColor: #123456 -> #0B6E69               |
|                      | - services.crm.enabled: false -> true                  |
|                      |                                                         |
|                      | Проверка                                                |
|                      | [OK] Схема соответствует контракту                     |
|                      | [OK] Нет секретных полей                               |
|                      | [!] CRM требует успешной проверки соединения           |
|                      |                                                         |
|                      | Причина изменения [________________________________]    |
|                      | [Сравнить с v30] [Отменить] [Запросить публикацию]      |
+----------------------+---------------------------------------------------------+
```

Назначение: подготовить атомарное изменение runtime-конфигурации. Значения по умолчанию продуктов сюда не копируются: они остаются встроенными в каждый продукт.

### 6. Версии и публикация конфигурации

```text
+--------------------------------------------------------------------------------+
| Конфигурации / Версии                                          [Новый черновик]|
+----------------------+---------------------------------------------------------+
|                      | Версия   Статус        Автор       Время       Действия |
|                      |---------------------------------------------------------|
|                      | v31      Черновик      И. Петров   10:42       [Открыть]|
|                      | v30      Опубликована  А. Иванова  09:45       [Сравнить]|
|                      | v29      Заменена      А. Иванова  вчера       [Открыть]|
|                      |                                                         |
|                      | Публикация v31                                         |
|                      | [ ] Проверка схемы и соединений пройдена               |
|                      | Причина [__________________________________________]   |
|                      |                    [Отмена] [Опубликовать v31]         |
+----------------------+---------------------------------------------------------+
```

Назначение: просматривать неизменяемую историю, сравнивать версии и публиковать проверенный черновик. Публикация создает новую ETag-версию; откат публикует новую версию с содержимым выбранной, а не изменяет историю.

```text
+--------------------------------------------------------------------------------+
| Аудит изменений                                               [Экспорт CSV]    |
+----------------------+---------------------------------------------------------+
|                      | Период [7 дней v] Автор [Все v] Тип [Все v] [Поиск]    |
|                      |---------------------------------------------------------|
|                      | Время   Автор       Объект         Действие             |
|                      |---------------------------------------------------------|
|                      | 10:42   И. Петров   config v31     draft.saved          |
|                      | 10:31   А. Иванова  CRM Core       endpoint.changed     |
|                      | 09:45   А. Иванова  config v30     published            |
|                      |                                                         |
|                      | Выбрано: config v30                                    |
|                      | Причина: обновлен фирменный цвет                        |
```

Назначение: расследовать изменение без возможности редактирования или удаления аудита. Запись содержит корреляционный идентификатор, исходный IP при наличии и ссылку на версию/сервис.

```text
+--------------------------------------------------------------------------------+

+----------------------+---------------------------------------------------------+
```

## Обязательные состояния страниц

Каждый список и каждая карточка проектируются со следующими состояниями: загрузка с каркасом, пустой результат с пояснением, ошибка с идентификатором запроса, недостаточные права, устаревшие данные и успешное завершение операции. Для мобильного экрана левая навигация сворачивается в меню, таблицы становятся карточками с приоритетными полями и ссылкой на детали.

## Шлюз согласования wireframes

**UI-код не начинается до явного одобрения пользователя.** До реализации необходимо показать пользователю этот набор wireframes и текстовое описание страниц, получить явное подтверждение (например, «да, одобряю»), и только после этого переходить к HTML/CSS/JS или компонентам интерфейса. Любые существенные изменения состава экранов или визуального направления требуют нового согласования.
