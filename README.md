# Admin Panel

> Проект находится на стадии документации. В репозитории пока нет реализованного приложения, интерфейса, API, схемы данных или конфигурации запуска.

Admin Panel планируется как самостоятельная административная система для централизованного управления брендингом, конфигурацией, каталогом и контрактами интеграции. Перед началом реализации должны быть согласованы пользовательские страницы, сценарии и архитектурные решения.

## Границы ответственности

Admin Panel будет владеть собственными данными и правилами для:

- брендинга и связанных настроек отображения;
- административной конфигурации в пределах своей предметной области;
- центрального каталога и его жизненного цикла;
- опубликованных контрактов интеграции и их совместимости.

Система центральной аутентификации на порту `7701` используется только как источник личности пользователя и ролей. Admin Panel не является владельцем учётных записей, паролей, сессий или глобальных ролей и не должен хранить их копии как источник истины.

Вне области проекта: реализация центральной аутентификации, владение данными других приложений, а также неоговорённые клиентские интерфейсы и интеграции.

## Планируемая топология

Номера портов зарезервированы для будущего локального развёртывания; процессы на них пока отсутствуют.

| Порт | Планируемое назначение | Статус |
| --- | --- | --- |
| `7701` | Центральная аутентификация: identity и roles | Внешняя зависимость |
| `7771` | API Admin Panel | Планируется |
| `7772` | Веб-интерфейс Admin Panel | Планируется |
| `7773` | PostgreSQL Admin Panel | Планируется |

Точные протоколы, маршруты, хранилище, модель развёртывания и назначение интеграционного контура будут зафиксированы отдельными ADR до реализации.

## Состояние и следующий этап

Текущий этап -- docs-first (implementation v1 now live). Реализация не начата, поэтому в репозитории намеренно отсутствуют инструкции по запуску, зависимости и готовые страницы.

Перед созданием кода необходимо:

1. Описать и согласовать страницы, роли, сценарии и критерии приёмки.
2. Подготовить план в `docs/plans/` и зафиксировать его в репозитории.
3. Оформить существенные архитектурные решения через ADR.
4. Согласовать контракты с зависимыми системами, включая границы использования auth на `7701`.
